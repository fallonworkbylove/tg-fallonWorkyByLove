# Fine-tuning gpt-4o-mini для бота

Цель: вместо обычного gpt-4o-mini + system prompt использовать свою
дообученную версию модели, которая сама, без длинных напоминаний в промпте,
отвечает в нужном стиле и по нужным сценариям.

Все скрипты лежат в `backend/scripts/`, запускать из папки `backend/`.

---

## 1. Подготовка датасета

Датасет — файл `.jsonl`, где каждая строка — один пример диалога в формате:

```json
{"messages": [
  {"role": "system", "content": "Ты Вика, 24 года. ..."},
  {"role": "user", "content": "а это не развод?"},
  {"role": "assistant", "content": "ой, я тоже сомневалась сначала) ..."}
]}
```

### Вариант А: автоматически из логов бота

Бот уже копит статистику удачных фраз в таблице `bot_patterns`
(`services/learningDb.js`) — только те пары "сообщение собеседника → ответ
бота", которые получили хорошую реакцию (`success_rate`). Экспортируем их:

```bash
cd backend
node scripts/export-finetune-dataset.js \
  --out=../training-data/finetune-dataset.jsonl \
  --min-uses=3 \
  --min-rate=0.7 \
  --system="Ты Вика, 24 года. ..." \
  --limit=2000
```

- `--min-uses=3` — фраза должна была сработать хотя бы 3 раза (иначе статистика случайна).
- `--min-rate=0.7` — минимум 70% реакций были хорошими.
- `--system` — системный промпт персонажа, который будет вписан в каждый пример. Если не задать — скрипт попробует взять первый непустой `prompt` из таблицы `accounts`.
- Без данных за плечами (мало диалогов) выборка будет маленькой — это нормально, значит рано делать fine-tuning, нужно больше живых диалогов.

### Вариант Б: свой готовый датасет

У вас уже есть датасет в нужном формате — можно использовать его отдельно
или объединить с автоматической выгрузкой:

```bash
node scripts/export-finetune-dataset.js \
  --out=../training-data/finetune-dataset.jsonl \
  --system="Ты Вика, 24 года. ..." \
  --merge=../training-data/manual-dataset.jsonl
```

`--merge` просто дописывает ваш файл в конец (с проверкой, что каждая строка — валидный JSON с полем `messages`).

**Минимум для запуска fine-tuning у OpenAI — 10 примеров**, но для реально
заметного эффекта в стиле/сценариях обычно нужно 50-100+ качественных
примеров, желательно покрывающих разные ситуации (возражения, NFT-подводка,
обычная болтовня) — сверьтесь с `stage` в `bot_patterns` (`--stage=objection_handling` и т.п.).

## 2. Загрузка датасета и запуск fine-tuning (Python)

Один раз установить зависимости:

```bash
pip install openai python-dotenv
```

Запуск (скрипт сам подхватит `OPENAI_API_KEY` из `backend/.env`):

```bash
cd backend/scripts
python3 finetune_openai.py \
  --file ../../training-data/finetune-dataset.jsonl \
  --base-model gpt-4o-mini-2024-07-18 \
  --suffix vika-v1
```

Скрипт:
1. локально проверяет формат `.jsonl` (чтобы не тратить деньги на кривой датасет);
2. загружает файл через `client.files.create(purpose="fine-tune")`;
3. создаёт задание `client.fine_tuning.jobs.create(...)`;
4. опрашивает статус каждые 30 секунд и печатает прогресс обучения, пока задание не завершится.

Если api.openai.com у вас блокируется по IP (как и у самого бота, см.
комментарий в `aiResponder.js`) — запускайте скрипт с машины с доступом
напрямую, либо задайте `ALL_PROXY=socks5://user:pass@host:port` перед
запуском (подхватится автоматически).

Если не хочется ждать в терминале — флаг `--no-wait` создаст задание и
сразу вернёт управление, статус можно посмотреть позже в
[OpenAI Dashboard → Fine-tuning](https://platform.openai.com/finetune).

## 3. Получение ID модели и подключение к проекту

По завершении скрипт печатает:

```
ГОТОВО! Fine-tuned модель обучена успешно.
model_id: ft:gpt-4o-mini-2024-07-18:org::abc123
```

Дальше — **минимальное изменение в коде не требуется вообще**: `aiResponder.js`
уже читает модель из `.env` (`OPENAI_MODEL`). Просто:

```bash
# в backend/.env
OPENAI_MODEL=ft:gpt-4o-mini-2024-07-18:org::abc123
```

```bash
pm2 restart all
```

Проверить, что подхватилось — в логах после перезапуска должна появиться строка:

```
[v0] Запрос к модели: "ft:gpt-4o-mini-2024-07-18:org::abc123" | baseURL: ...
```

## 4. Откат / безопасность

В `.env` добавлена ещё одна переменная — запасная модель:

```bash
OPENAI_MODEL_FALLBACK=gpt-4o-mini
```

Если основная (fine-tuned) модель вдруг вернёт ошибку — например, OpenAI
удалила старую fine-tuned модель за неактивность, — бот автоматически
переключится на `OPENAI_MODEL_FALLBACK` для этого запроса, а не промолчит.
Такие случаи видно в логах (`пробую запасную`) и в отчёте по расходам (поле
`fell_back`, см. ниже).

Чтобы откатиться на обычную модель вручную — просто сотри/замени `OPENAI_MODEL`
в `.env` и перезапусти pm2, никаких других изменений не нужно.

---

## 5. Отслеживание стоимости

Каждый запрос к модели теперь логируется в таблицу `openai_usage_log`
(создаётся автоматически, `services/finetuneUsage.js`) с реальными токенами
из ответа API и посчитанной стоимостью по табличным ценам.

Посмотреть отчёт за последние 7 дней:

```bash
cd backend
node scripts/finetune-cost-report.js --days=7
```

Выведет разбивку по моделям (сколько запросов, токены in/out, $ и сколько
раз сработал фолбэк) и по дням.

**Важно:** цены на fine-tuned модели зашиты в `MODEL_PRICING` внутри
`services/finetuneUsage.js` — сверяйте их с
[platform.openai.com/pricing](https://platform.openai.com/docs/pricing) и
правьте при изменении тарифов OpenAI (API не отдаёт цену сам).

Стоимость самого обучения (разовая, за прогон датасета) выводится в конце
работы `finetune_openai.py` (примерная оценка по `job.trained_tokens`).

---

## Краткий чек-лист

1. `node scripts/export-finetune-dataset.js ...` → получить `.jsonl`.
2. `pip install openai python-dotenv` (один раз).
3. `python3 finetune_openai.py --file ...` → дождаться `model_id`.
4. Вписать `OPENAI_MODEL=ft:...` в `backend/.env`, `pm2 restart all`.
5. Через день-два — `node scripts/finetune-cost-report.js --days=2`, сверить расходы и `fell_back`.
